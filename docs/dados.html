Os perfis do diretório também estão descritos em RDF. Esta página reúne os arquivos, as seis perguntas de competência com suas consultas SPARQL e as ligações das áreas de conhecimento com o Wikidata.

Os resultados abaixo foram exportados de uma execução local sobre o conjunto de demonstração (Universidade Demonstrativa). Não há endpoint SPARQL público.

Consultas SPARQL

Cada consulta foi executada com RDFLib sobre instancias.ttl, sem inferência. Os parâmetros entram como URIs; valores sem registro aparecem como “Não informado”. PC4 e PC5 percorrem relações entre tipos diferentes de entidade: projeto e pessoas, publicação e autores.

PC1. Quais são os docentes cadastrados e seus respectivos departamentos ou unidades acadêmicas?

Ver consulta SPARQL
# PC1 — Quais são os docentes cadastrados e seus respectivos departamentos
# ou unidades acadêmicas?
#
# Parâmetros: nenhum. A consulta lista todos os docentes do grafo.
# Percurso: ?docente (ca:Docente) --ca:temVinculoDocente--> ?unidade.
# Pessoas apenas discentes ficam fora porque o padrão exige o tipo ca:Docente
# e o vínculo docente; o vínculo discente (ca:temVinculoDiscente) não é usado.

PREFIX ca:     <https://pedromota07.github.io/conecta-academico/ontologia/conecta-academico.ttl#>
PREFIX schema: <https://schema.org/>

SELECT ?docente ?nomeDocente ?unidade ?nomeUnidade
WHERE {
  ?docente a ca:Docente ;
           schema:name ?nomeDocente ;
           ca:temVinculoDocente ?unidade .
  ?unidade schema:name ?nomeUnidade .
}
ORDER BY ?nomeDocente ?docente ?nomeUnidade ?unidade

# PC2 — Quais discentes pertencem a determinado curso?
#
# Parâmetro obrigatório: ?curso — URI de um ca:CursoGraduacao.
#   O executor (codigo-fonte/executar_consultas.py) fornece o valor como
#   URIRef em initBindings. Em outra ferramenta SPARQL 1.1, acrescente no
#   início do WHERE, por exemplo:
#     VALUES ?curso { <https://pedromota07.github.io/conecta-academico/ontologia/instancias.ttl#curso-sistemas-informacao> }
# Percurso: ?discente (ca:Discente) --ca:matriculadoEm--> ?curso.
# A seleção usa a identidade (URI) do curso, nunca o nome de exibição.

PC3. Quais docentes atuam em determinada área de pesquisa?

Ver consulta SPARQL
# PC3 — Quais docentes atuam em determinada área de pesquisa?
#
# Parâmetro obrigatório: ?area — URI de uma ca:AreaConhecimento (skos:Concept).
#   Em outra ferramenta SPARQL 1.1, acrescente no início do WHERE, por exemplo:
#     VALUES ?area { <https://pedromota07.github.io/conecta-academico/ontologia/instancias.ttl#area-dados-abertos> }
# Percurso: ?docente (ca:Docente) --ca:atuaEmArea--> ?area.
# ca:temInteresseEmArea (interesse discente) não é atuação docente e não é
# consultado. Só a área registrada conta: não há expansão por skos:broader.

PREFIX ca:     <https://pedromota07.github.io/conecta-academico/ontologia/conecta-academico.ttl#>
PREFIX schema: <https://schema.org/>
PREFIX skos:   <http://www.w3.org/2004/02/skos/core#>

SELECT ?area ?rotuloArea ?docente ?nomeDocente
WHERE {
  ?area a ca:AreaConhecimento ;
        skos:prefLabel ?rotuloArea .
  ?docente a ca:Docente ;
           ca:atuaEmArea ?area ;
           schema:name ?nomeDocente .
}
ORDER BY ?nomeDocente ?docente

PC4. Quais docentes e discentes participam de um mesmo projeto de pesquisa?

Ver consulta SPARQL
# PC4 — Quais docentes e discentes participam de um mesmo projeto de pesquisa?
#
# Parâmetros: nenhum. A consulta lista todos os pares docente/discente por projeto.
# Percurso (relação entre tipos de entidade):
#   ?projeto (ca:ProjetoPesquisa) --ca:temParticipante--> ?docente  (ca:Docente)
#   ?projeto (ca:ProjetoPesquisa) --ca:temParticipante--> ?discente (ca:Discente)
# As duas participações se cruzam pela mesma URI de projeto, portanto projetos
# com títulos iguais continuam distintos. O FILTER exige duas pessoas
# diferentes: quem acumula os dois papéis não forma um par sozinho.
# A associação de um grupo ao projeto (ca:associadoAoProjeto) não é usada,
# pois não comprova participação individual.

PREFIX ca:      <https://pedromota07.github.io/conecta-academico/ontologia/conecta-academico.ttl#>
PREFIX schema:  <https://schema.org/>
PREFIX dcterms: <http://purl.org/dc/terms/>

SELECT ?projeto ?tituloProjeto ?docente ?nomeDocente ?discente ?nomeDiscente
WHERE {
  ?projeto a ca:ProjetoPesquisa ;
           dcterms:title ?tituloProjeto ;
           ca:temParticipante ?docente , ?discente .
  ?docente a ca:Docente ;
           schema:name ?nomeDocente .
  ?discente a ca:Discente ;
            schema:name ?nomeDiscente .
  FILTER (?docente != ?discente)
}
ORDER BY ?tituloProjeto ?projeto ?nomeDocente ?docente ?nomeDiscente ?discente

PC5. Quais publicações estão associadas a determinado docente e quem são seus coautores, quando essa informação estiver representada?

Ver consulta SPARQL
# PC5 — Quais publicações estão associadas a determinado docente e quem são
# seus coautores, quando essa informação estiver representada?
#
# Parâmetro obrigatório: ?docente — URI de uma pessoa com tipo ca:Docente.
#   Em outra ferramenta SPARQL 1.1, acrescente no início do WHERE, por exemplo:
#     VALUES ?docente { <https://pedromota07.github.io/conecta-academico/ontologia/instancias.ttl#pessoa-ana> }
# Percurso (relação entre tipos de entidade):
#   ?publicacao (ca:Publicacao) --ca:temAutor--> ?docente
#   ?publicacao (ca:Publicacao) --ca:temAutor--> ?coautor (outra ca:Pessoa)
# Usa apenas ca:temAutor. schema:author também está no grafo, com os mesmos
# pares, mas combinar os dois predicados duplicaria linhas.
# O FILTER fica dentro do OPTIONAL: exclui o próprio docente da lista de
# coautores sem descartar a publicação que não tem outro autor registrado.
# Nesse caso ?coautor fica sem valor (não associado). Ausência de registro
# não comprova autoria exclusiva. O coautor não precisa ter perfil (papel).

PREFIX ca:      <https://pedromota07.github.io/conecta-academico/ontologia/conecta-academico.ttl#>
PREFIX schema:  <https://schema.org/>
PREFIX dcterms: <http://purl.org/dc/terms/>

SELECT ?docente ?nomeDocente ?publicacao ?tituloPublicacao ?ano ?coautor ?nomeCoautor
WHERE {
  ?docente a ca:Docente ;
           schema:name ?nomeDocente .
  ?publicacao a ca:Publicacao ;
              ca:temAutor ?docente ;
              dcterms:title ?tituloPublicacao .
  OPTIONAL { ?publicacao ca:anoPublicacao ?ano }
  OPTIONAL {
    ?publicacao ca:temAutor ?coautor .
    FILTER (?coautor != ?docente)
    OPTIONAL { ?coautor schema:name ?nomeCoautor }
  }
}
ORDER BY ?tituloPublicacao ?publicacao ?nomeCoautor ?coautor

PC6. Quais pessoas estão vinculadas a uma unidade acadêmica específica, independentemente de serem docentes ou discentes?

Ver consulta SPARQL
# PC6 — Quais pessoas estão vinculadas a uma unidade acadêmica específica,
# independentemente de serem docentes ou discentes?
#
# Parâmetro obrigatório: ?unidade — URI de uma ca:UnidadeAcademica.
#   Em outra ferramenta SPARQL 1.1, acrescente no início do WHERE, por exemplo:
#     VALUES ?unidade { <https://pedromota07.github.io/conecta-academico/ontologia/instancias.ttl#unidade-computacao> }
# Percurso: ?pessoa --(ca:temVinculoDocente | ca:temVinculoDiscente)--> ?unidade.
# O caminho alternativo reúne os dois vínculos diretos; DISTINCT deixa uma
# linha por pessoa, e os dois EXISTS indicam quais papéis ela tem nessa
# unidade (xsd:boolean). ca:temUnidadeResponsavel (curso) e
# ca:temUnidadeSuperior (hierarquia) não são vínculos de pessoas e não são
# seguidos: consultar um instituto não traz pessoas de seus departamentos.

PREFIX ca:     <https://pedromota07.github.io/conecta-academico/ontologia/conecta-academico.ttl#>
PREFIX schema: <https://schema.org/>

SELECT DISTINCT ?unidade ?nomeUnidade ?pessoa ?nomePessoa ?vinculoDocente ?vinculoDiscente
WHERE {
  ?unidade a ca:UnidadeAcademica ;
           schema:name ?nomeUnidade .
  ?pessoa ca:temVinculoDocente|ca:temVinculoDiscente ?unidade ;
          schema:name ?nomePessoa .
  BIND (EXISTS { ?pessoa ca:temVinculoDocente ?unidade } AS ?vinculoDocente)
  BIND (EXISTS { ?pessoa ca:temVinculoDiscente ?unidade } AS ?vinculoDiscente)
}
ORDER BY ?nomePessoa ?pessoa

Quais áreas locais estão ligadas a recursos externos e por qual relação de mapeamento SKOS?

Consulta complementar, fora das seis perguntas de competência.

Ver consulta SPARQL
# Consulta complementar (não é uma das seis perguntas de competência).
# Lista as ligações das áreas locais com recursos externos (LOD).
#
# Parâmetros: nenhum.
# Percurso: ?area (ca:AreaConhecimento) --?relacao--> ?recursoExterno, onde
# ?relacao é uma das relações de mapeamento SKOS. O FILTER descarta alvos
# dentro do namespace do próprio projeto.

PREFIX ca:   <https://pedromota07.github.io/conecta-academico/ontologia/conecta-academico.ttl#>
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>

SELECT ?area ?rotuloArea ?relacao ?recursoExterno
WHERE {
  VALUES ?relacao { skos:exactMatch skos:closeMatch skos:broadMatch skos:narrowMatch skos:relatedMatch }
  ?area a ca:AreaConhecimento ;
        skos:prefLabel ?rotuloArea ;
        ?relacao ?recursoExterno .
  FILTER (isIRI(?recursoExterno)
          && !STRSTARTS(STR(?recursoExterno), "https://pedromota07.github.io/conecta-academico/"))
}
ORDER BY ?rotuloArea ?area ?relacao ?recursoExterno

Ligações externas

As áreas de conhecimento locais são conceitos SKOS. Três delas têm correspondência com itens do Wikidata. A URI da entidade (forma canônica publicada pela fonte) é diferente da página que a descreve. Não há ligação de pessoas fictícias com identidades reais.

  • Dados abertos inst:area-dados-abertos → skos:closeMatch → http://www.wikidata.org/entity/Q309901 (open data, página da fonte)

    O item descreve dados acessíveis e utilizáveis por outras pessoas e é classificado como conceito e campo de trabalho. A área local trata da publicação desses dados como tema de pesquisa. Os referentes são comparáveis, mas o recorte local é mais estreito, por isso a correspondência é próxima e não exata.

    Conferido em 21/11/2026.

  • Web Semântica inst:area-web-semantica → skos:closeMatch → http://www.wikidata.org/entity/Q54837 (Semantic Web, página da fonte)

    O item é classificado como campo de estudo e disciplina acadêmica, além de descrever a extensão da Web para troca de dados. A área local corresponde ao campo de estudo. Como o item externo também abrange a tecnologia, a correspondência é próxima e não exata.

    Conferido em 21/11/2026.

  • Curadoria digital inst:area-curadoria-digital → skos:closeMatch → http://www.wikidata.org/entity/Q5276060 (digital curation, página da fonte)

    O item descreve seleção, preservação, manutenção, coleta e arquivamento de ativos digitais e é subclasse de curadoria. A definição local cobre seleção, documentação e preservação. Os conceitos são muito próximos, mas a correspondência próxima evita propagar equivalências por transitividade.

    Conferido em 21/11/2026.

Como reproduzir

python -B codigo-fonte/gerar_rdf.py --publicaveis docs/ontologia
python -B codigo-fonte/executar_consultas.py
python -B codigo-fonte/executar_consultas.py consulta02 --param curso=curso-biblioteconomia
python -B codigo-fonte/gerar_site.py

A explicação de cada consulta está em documentacao/consultas-sparql.md e a das ligações em documentacao/ligacoes-externas.md, no repositório do projeto.
